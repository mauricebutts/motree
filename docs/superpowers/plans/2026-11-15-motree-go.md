# motree Go Rewrite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the bash `mt` (motree) tool to a single Go binary with full
behavioral parity (including the not-yet-committed `mt pr`), JSON state
storage at an env-var-configurable path, and hook-based status detection
replacing tmux pane-text scraping.

**Architecture:** A thin `cmd/mt` dispatcher over focused internal
packages: `executil` (shared subprocess-running abstraction, fakeable in
tests), `state` (JSON session store), `gitutil`/`tmux`/`ghutil`
(subprocess wrappers), `statusfile` (hook-driven status files), and
`mtcmd` (the actual `create`/`spawn`/`pr`/`ls`/`rm` orchestration logic
that composes the above). Every subprocess-driving package takes an
injected `executil.Runner`, so command construction is unit-tested via a
fake runner without needing a live `tmux`/`git`/`gh`/`fzf` environment;
`git` additionally gets real integration tests since it's fast and local.

**Tech Stack:** Go 1.27, stdlib only (`flag`-based subcommand dispatch,
`encoding/json`, `os/exec`) — no third-party CLI framework or dependencies.

**Spec:** `docs/superpowers/specs/2026-11-14-motree-go-design.md`

## Global Constraints

- Worktree path: `<repo-root>/.claude/worktrees/<name>`. Branch name ==
  session name.
- Base branch resolution: `-b` flag, else `origin/HEAD` (symbolic-ref),
  else `main`. A newly created branch gets `--unset-upstream` after being
  created off `origin/<base>`.
- Before creating ANY new worktree (`mt <name>`, `mt spawn`, and `mt pr`
  alike — only when the worktree directory doesn't already exist), run
  `git worktree prune` first. `mt <name>`/`mt spawn` additionally run
  `git fetch origin <base-branch>` before resolving `BranchExists`/
  creating the branch; a fetch failure is non-fatal — print `motree: fetch
  failed, using local refs` to stderr and continue with whatever local
  refs exist. `mt pr` does not fetch a base branch (there is none — `gh pr
  checkout` fetches the PR's own branch itself), but still prunes first.
- Window/pane layout: `nvim .` (left, full height), shell (top right),
  `claude`/`claude -c` (bottom right); right column 25% width, split
  top/bottom.
- Resume detection: use `claude -c` iff `~/.claude/projects/<escaped-cwd>`
  exists and is non-empty. Escaping = replace `.`, `/`, `_` with `-`.
- `mt spawn`: errors if `<name>` already exists; fixed tmux size `-x 200
  -y 50`; sends the prompt via quoted `send-keys`; never attaches.
- `mt pr <pr_number>`: numeric-only validation; requires `gh` on PATH;
  session/worktree name `pr-<pr_number>`; no `-b`/`-d` flags; if `gh pr
  view <n> --json headRefName --jq .headRefName` is empty, print exactly
  `no pr found` and exit 1 with no worktree/session/state created;
  otherwise `git worktree add --detach`, then `gh pr checkout <n>` run
  with that worktree as cwd; claude pane launched straight into the fixed
  prompt `Please give a high level explanation of this PR and it's
  business purpose`; attaches at the end (unlike `spawn`).
- `mt ls` row label format: `<emoji> <name> | <Mon YYYY-MM-DD HH:MM>
  (<repo,repo,...>) — <description|"(no description)">` — note the space
  between the emoji and the name, and the abbreviated weekday (`Mon`) at
  the start of the date (bash: `date -r "$ts" '+%a %Y-%m-%d %H:%M'`; Go:
  `time.Unix(ts, 0).Format("Mon 2006-01-02 15:04")`, local time). Emoji:
  🔔 waiting, 🏃 running, 🤖 subagents, 🛑 stopped, none (and no trailing
  space) if no status found. When a session has multiple repos/worktrees,
  aggregate priority is waiting > running > subagents > stopped > (none).
- `mt rm`: if any repo's `git worktree remove` fails, abort the *entire*
  operation before touching state, printing the real git stderr text; no
  partial removal. `git branch -d` is best-effort (ignored on failure).
  `tmux kill-session` only runs if a live session is found.
- State file path: env var `MOTREE_STATE_FILE`, default `$HOME/.motree`.
  For all work in this plan, set `MOTREE_STATE_FILE=$HOME/.motree-dev`
  (never touch the real `~/.motree` or the `.zshrc` alias).
- Status file directory: `<state file path>-status/` (e.g.
  `~/.motree-dev-status/`), one file per escaped-cwd, same escaping as
  resume detection.
- Hook event → status mapping (final): `SessionStart`→stopped,
  `UserPromptSubmit`→running, `PreToolUse`→running, `PostToolUse`→running,
  `Notification`→waiting, `PermissionRequest`→waiting,
  `SubagentStop`→subagents, `Stop`→stopped, `StopFailure`→stopped,
  `SessionEnd`→clear (delete the status file). Any other event name is a
  no-op.
- `mt __hook` (hidden subcommand invoked by Claude Code) must always exit
  0 regardless of internal error — it must never interfere with Claude
  Code's own tool/permission flow. Errors go to stderr only.
- `mt install-hooks` merges hook entries for the above event set
  additively into `~/.claude/settings.json`'s `hooks` block (pointing at
  `<mt binary path> __hook`), without disturbing existing entries (e.g.
  iTerm2's `cc-status`) or other top-level settings keys, and is
  idempotent on repeat runs.
- Never reimplement `git`, `tmux`, `fzf`, `gh`, `curl`, `nvim`, or
  `claude` — always shell out.
- Module path `github.com/mauricebutts/motree`, Go 1.27.

## Review Focus

- Running `mt`/`mt pr` outside a git repo must print exactly `motree: not
  inside a git repo` and exit non-zero, not panic — tested in Task 9
  (create) and Task 11 (pr).
- A session name containing a `.` must still resolve correctly — tmux
  reads `.` in a bare `-t name` target as a pane separator, so every call
  after creation must target the resolved session ID, never the raw name
  — tested in Task 9 (create).
- `mt rm` on a session whose tmux session was already killed manually
  (state/worktree still exist) must still remove the worktree, branch,
  and state rows, skipping only the now-pointless `kill-session` call —
  tested in Task 14 (rm).
- `mt __hook` firing for a `cwd` that isn't any tracked session's
  worktree path must still write/clear its status file without error —
  status files are keyed purely by cwd, independent of `mt`'s own state —
  tested in Task 5 (statusfile) and Task 6 (`mt __hook`).
- Two `mt` processes calling `State.Save` at nearly the same moment must
  never corrupt `MOTREE_STATE_FILE` into invalid JSON (last-writer-wins is
  acceptable; corruption is not) — tested in Task 2 (state).
